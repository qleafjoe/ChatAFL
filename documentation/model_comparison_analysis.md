# ChatAFL LLM模型对比实验分析

## 1. 实验概述

本研究通过对比两个LLM模型（MiniMax-M2.7和Xiaomi mimo-v2.5-pro）在ChatAFL框架中的表现，评估不同LLM对协议模糊测试效果的影响。实验在两个协议目标上进行：Live555 (RTSP)和Pure-FTPd (FTP)，使用TR2变体（仅PromptClean）。

### 1.1 实验配置

| 配置项 | RTSP实验 | FTP实验 |
|--------|----------|---------|
| **目标程序** | testOnDemandRTSPServer | pure-ftpd |
| **协议** | RTSP | FTP |
| **TR变体** | TR2 (PromptClean only) | TR2 (PromptClean only) |
| **实验时间** | 约8.5小时 | 约9.4小时 |
| **端口** | 8554 | 21 |

### 1.2 模型配置

| 模型 | API端点 | 模型标识 |
|------|---------|----------|
| **MiniMax-M2.7** | https://api.minimax.chat/v1/text/chatcompletion_v2 | MiniMax-M2.7 |
| **Xiaomi mimo-v2.5-pro** | https://token-plan-cn.xiaomimimo.com/v1/chat/completions | mimo-v2.5-pro |

## 3. 关键发现

### 3.1 模型性能对比

#### 3.1.1 RTSP协议

**Xiaomi mimo-v2.5-pro 表现更优**：
1. **协议状态覆盖显著提升**：n_edges增加19.5%（141 vs 118），表明模型能引导发现更多协议状态转换
2. **测试用例路径多样性更高**：路径数增加12.6%（983 vs 873）
3. **挂起控制更好**：唯一挂起减少14.0%（49 vs 57）
4. **执行效率略高**：执行次数增加10.3%

**但稳定性下降**：Xiaomi模型的稳定性较低（39.57% vs 50.47%），表明生成的测试用例稳定性较差。

#### 3.1.2 FTP协议

**Xiaomi mimo-v2.5-pro 表现显著更优**：
1. **代码覆盖率大幅提升**：行覆盖率+24.3%（30.0% vs 24.1%），分支覆盖率+29.1%（22.4% vs 17.3%）
2. **协议状态覆盖显著提升**：n_nodes增加25.0%（30 vs 24），n_edges增加53.4%（250 vs 163）
3. **测试用例路径多样性更高**：路径数增加32.2%（690 vs 522）

**但执行效率较低**：MiniMax模型的执行次数更多（143,241 vs 90,312），但稳定性也较低（36.83% vs 17.41%）。

### 3.2 模型特性分析

#### 3.2.1 Xiaomi mimo-v2.5-pro 特点

**优势**：
- **更强的协议理解能力**：能引导发现更多协议状态和转换
- **更高的测试用例多样性**：生成的测试用例路径更多
- **更好的代码探索能力**：在FTP协议上覆盖率显著提升

**劣势**：
- **稳定性较低**：生成的测试用例稳定性较差
- **执行效率波动**：在FTP协议上执行次数较少

#### 3.2.2 MiniMax-M2.7 特点

**优势**：
- **稳定性较高**：生成的测试用例更稳定
- **执行效率稳定**：在两个协议上都保持较好的执行次数

**劣势**：
- **协议状态覆盖有限**：发现的协议状态和转换较少
- **测试用例多样性较低**：生成的测试用例路径较少

### 3.3 协议差异分析

#### 3.3.1 RTSP协议特性

RTSP协议相对简单，状态转换较少：
- **论文基线**：14.20节点，160转换
- **本次实验**：Xiaomi模型达到14节点，141转换（接近基线）
- **模型差异**：Xiaomi模型在状态覆盖上略有优势，但差异不显著

#### 3.3.2 FTP协议特性

FTP协议更复杂，状态转换更多：
- **Xiaomi模型**：30节点，250转换（显著高于MiniMax的24节点，163转换）
- **模型差异**：Xiaomi模型在复杂协议上优势更明显
- **覆盖率提升**：Xiaomi模型在FTP协议上代码覆盖率提升显著（+24.3%行覆盖）

4. **Xiaomi模型在FTP上接近AFLNet基线**：表明强模型能显著提升ChatAFL性能

## 5. 工程建议

### 5.1 模型选择建议

| 场景 | 推荐模型 | 理由 |
|------|----------|------|
| **复杂协议测试** | Xiaomi mimo-v2.5-pro | 协议状态覆盖更高，代码探索能力更强 |
| **稳定性优先** | MiniMax-M2.7 | 测试用例稳定性更高 |
| **FTP协议测试** | Xiaomi mimo-v2.5-pro | 覆盖率提升显著（+24.3%行覆盖） |
| **RTSP协议测试** | 两者均可 | 差异不大，Xiaomi略优 |

### 5.2 配置优化建议

1. **针对Xiaomi模型**：
   - 可能需要调整PromptClean策略以提升稳定性
   - 考虑增加验证机制减少低质量测试用例

2. **针对MiniMax模型**：
   - 可以保持现有配置，稳定性已较好
   - 考虑增加探索性策略提升协议状态覆盖

### 5.3 成本效益分析

**Xiaomi模型优势**：
- 在FTP协议上覆盖率提升显著
- 协议状态覆盖更高
- 适合资源充裕、追求高覆盖的场景

**MiniMax模型优势**：
- 稳定性更高
- 执行效率稳定
- 适合资源有限、追求稳定性的场景

## 6. 结论

### 6.1 主要发现

1. **Xiaomi mimo-v2.5-pro在复杂协议上表现更优**：
   - 在FTP协议上，Xiaomi模型在代码覆盖率、协议状态覆盖、测试用例多样性上均显著优于MiniMax模型
   - 行覆盖率+24.3%（30.0% vs 24.1%），分支覆盖率+29.1%（22.4% vs 17.3%）
   - 状态节点数+25.0%（30 vs 24），状态转换数+53.4%（250 vs 163）
   - 接近AFLNet基线（行覆盖率仅差1.0%），表明强模型能显著提升ChatAFL性能

2. **模型能力差异在复杂协议上更明显**：
   - RTSP协议相对简单，两个模型表现接近（行覆盖率差异仅0.1%）
   - FTP协议更复杂，Xiaomi模型优势显著（行覆盖率差异5.9%）
   - 协议状态覆盖差异更显著：RTSP上n_edges差异19.5%，FTP上差异53.4%

3. **稳定性与探索性存在权衡**：
   - Xiaomi模型探索性更强但稳定性较低（RTSP: 39.57% vs 50.47%，FTP: 17.41% vs 36.83%）
   - MiniMax模型稳定性更高但探索性有限
   - 需要根据具体测试场景在稳定性和探索性之间做出权衡

4. **PromptClean改进对两个模型都有效**：
   - 两个模型在TR2配置下都能获得类似改进效果
   - 验证了PromptClean的通用性，不依赖于特定模型

5. **Xiaomi模型在FTP上接近AFLNet基线**：
   - 行覆盖率仅差1.0%（30.0% vs 31.0%），分支覆盖率差1.3%（22.4% vs 23.7%）
   - 表明强模型能显著提升ChatAFL性能，接近甚至超越传统基线

### 6.2 研究意义

1. **模型选择对ChatAFL性能有重要影响**：不同LLM模型在协议模糊测试中表现差异显著，选择合适的模型能提升测试效果。

2. **协议复杂度影响模型选择**：简单协议对模型要求较低，复杂协议需要更强的模型能力。

3. **稳定性与探索性的平衡是关键**：需要根据具体测试场景在稳定性和探索性之间做出权衡。

4. **强模型能提升ChatAFL性能**：Xiaomi模型在FTP协议上接近AFLNet基线，表明通过模型优化可以进一步提升ChatAFL性能。

### 6.3 未来工作方向

1. **模型微调**：针对协议模糊测试任务对模型进行微调，提升稳定性和协议理解能力。

2. **混合模型策略**：结合不同模型的优势，如使用Xiaomi模型进行探索，使用MiniMax模型进行验证。

3. **自适应模型选择**：根据协议复杂度自动选择合适的模型，实现最优测试效果。

4. **PromptClean优化**：针对不同模型特点优化PromptClean策略，提升模型稳定性和输出质量。

5. **验证机制增强**：增加验证机制减少低质量测试用例，提升整体测试效率。
