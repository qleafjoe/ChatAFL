# ChatAFL-TR4：Hard Validation + Feedback Retry + Soft Validation

## 定位

在 TR3 严格验证基础上增加概率性软接受机制，为"几乎有效"的 LLM 输出提供安全网。

## 消融配置

| 标志 | 值 | 说明 |
|------|----|------|
| Hard Validation | **ON** | 严格验证（格式+语法+上下文） |
| Feedback Retry | **ON (3次)** | 验证失败时反馈错误信息并重试 |
| Soft Accept | **ON (概率)** | 验证+重试均失败后的概率性接受 |
| Contextual Recovery | OFF | 无上下文修复 |
| 状态转换图 | 保留 | 协议一致性检查启用 |
| 上下文感知拒绝检测 | 保留 | 协议指标预检查 |
| LF→CRLF 转换 | 保留 | 协议格式修正 |
| 指数退避重试 | 保留 | 指数退避（上限 30s） |
| 语法解析鲁棒性 | 保留 | JSON 防御性检查 |

## 软接受概率

| 验证失败类型 | 接受概率 | 说明 |
|-------------|---------|------|
| `FORMAT_FAIL` | **0%** | 格式错误绝不放过 |
| `GRAMMAR_FAIL` | **5%** | 语法错误低概率接受 |
| `CONTEXT_FAIL` | **30%** | 上下文错误较高概率接受 |

## 核心特征

- 严格验证 + 反馈重试（与 TR3 相同）
- 验证+重试均失败后，调用 `should_soft_accept_llm_result()` 进行概率判定
- 软接受的种子调度优先级降低：`perf_score` 缩减 2/10（`TR_SOFT_SEED_PRIORITY=2`）
- 软接受的种子保存为 `soft_enriched_*` 而非 `enriched_*`，便于后续分析
- 新增 `llm_seed_priority` 字段用于种子优先级管理

## 与 TR3 的关键差异

### afl-fuzz.c（11514 行 vs 基线 11594 行，-80 行）

**新增**：
- `should_soft_accept_llm_result()` — 概率性软接受判定函数
- `llm_seed_priority` 字段（`queue_entry` 结构体）
- `calculate_perf_score()` 中的优先级缩放逻辑
- 停滞处理和种子丰富中的软接受分支

**仍移除**（与 TR3 相同）：
- 种子去重哈希表和去重逻辑
- 动态变异阶段权重
- 运行时环境变量解析

## 处理流程

```
LLM 生成候选
    ↓
严格验证 ──通过──→ 接受
    ↓ 失败
反馈重试（最多3次）──通过──→ 接受
    ↓ 仍失败
概率软接受 ──命中──→ 接受（降低优先级）
    ↓ 未命中
拒绝
```

## 行为总结

TR4 在 TR3 基础上增加了概率安全网。即使验证失败且重试无效，仍有小概率保留"几乎有效"的种子（以降低调度优先级为代价）。消融实验中用于测量"保留近似有效种子"对覆盖率的贡献，与 TR5 的"上下文修复"策略形成对比。
